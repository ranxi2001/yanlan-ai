# 覆盖检查与按需拆短复核：实现和实测

2026-09-10。已实现真实音频驱动的覆盖检查、预算路由、拆短复核、局部证据接纳及尾部补回。**发现并自动定位了一处 25.5 秒窗口的严重漏转，说明只保持 30 秒也不够。开发集修复后 CER 从 13.96% 降到 12.62%；原留出片段维持 5.29%，尚未证明留出准确率提升。**

## 实际执行规模

- 新下载 3 场此前未评分的 AISHELL-4 会议，共 **6768.458 秒（112 分 48 秒）**。开发为 `L_R004S02C01`；最初留出为 `S_R003S01C01`、`M_R003S02C01`。与前两轮使用的 4 场会议 ID 不重叠，不据此声称说话人独立或基础模型未见过数据。
- 三场完整音频都实际转写。严格 CER 另在 **9 个连续无重叠区间、754.059 秒**上计算：开发 2378 个参考字符，留出 1134 个。没有将完整会议的重叠发言串接后冒充普通 CER。
- MiMo 约 30 秒基线 **250 次请求**；选择 **18 个窗口**，追加 **36 次远端短片请求**，合计 **286 次**，全部成功。
- 最终本地 SenseVoice 扫描 **510 个短片**。开发过程中发现微小尾片后重新扫描一次，因此实际本地推理总计 **1020 个短片**；旧扫描和旧计划保留为 `scout-initial.json`、`coverage-plan-initial.json`。
- 来源版本、声道和音频/参考哈希见[来源规格](../data/hf-asr-coverage-sources.json)、[样本锁](../data/hf-asr-coverage-lock.json)。依旧使用原声道 0、16 kHz PCM16；许可证说明沿用[HF 数据说明](hf-asr-benchmark-2026-09-09.md)。

尾部规则是在看过开发案例后增加的，复用了已取得的声学结果，没有再调用 ASR。此时原留出成绩也已读过，因此最后一列修复结果只能称为**开发后回放与回归**，不是新的全盲留出验证。原留出的 9 个核心窗口中，主识别和本地扫描的分歧较低，没有触发复核。不能把“没有改动所以没有退步”当成已证明能改善困难留出数据。

开发集最终的替换/删除/插入为 **131/81/88**，基线为 **128/116/88**：删除减少 35，替换增加 3，净减少 32 个编辑错误。合计下降主要来自一个开发案例，不宣称稳定的跨会议百分比收益。

## 真实漏转案例

开发区间 `L_R004S02C01-clean-6` 的第 1 个核心窗口长 **25.456 秒**，VAD 有效语音约 **23.296 秒**。MiMo 返回 72 个归一化字符，文本流畅，原有质量门通过；本地 SenseVoice 短片返回 136 个字符，检测到 65 个相对缺失字符，分歧率约 50.74%，自动触发了复核。

原稿停在：

> ……这这天光剩下烦了就

拆短 MiMo 与 SenseVoice 都还识别出了清理广告、安全通道垃圾、外来人员登记等后续发言。两个后端在后半段个别词上有分歧；修订规则只追加先出现且两路一致的部分：

> ……啊这这个我们知道了不是说嘛，然后下去之后先安排保洁部门把那些小广告清理掉，

它追加了 **35 个归一化字符**，保留原稿已有文字，严格计分净减少 **32 个错误**。剩余分歧没有被强行写入正文。例如拆短 MiMo 还把已有“舒适”识别成“收拾”，该改动没有获得自动接纳。

最终在所有完整录音和评分片段上共接纳 **5 处变更**：初版 3 处局部词面变化，后续 2 处尾部追加。其中上述评分区间的一处有可计算的金标准收益；其余 4 处缺少本轮局部非重叠参考诊断要求的唯一锚点，**未判定改对/改错，不能称为 5 处正确纠错**。完整录音仍需听音/重叠语音评测。

## 核心工具与规则

[覆盖 Harness](../src/asr-coverage-harness.js)提供：

- `planCoverageParts`：在核心音频范围内按静音点规划通常 10～20 秒的短片；若尾片不足 10 秒，就重新均分最后两片。音频连续、无重叠、不丢采样点。原核心窗口本身不足 10 秒时保留整片。本次消除了原方案中的 96 毫秒尾片。
- `assessAsrCoverage`：检查有效语音时长、文字密度、本地主识别分歧和相对缺失内容。有效语音至少 5 秒但文字密度低于 0.9 字/秒，或相对缺失至少 8 字且占本地输出至少 18%，或分歧率至少 35%，会形成风险信号。已有质量异常也可触发；两路为空且 VAD 近乎静音时不浪费复核预算。
- `planAsrCoverageReviews`：只按原音频和模型输出排序，不读取参考答案。按完整/干净区间、开发/留出分别汇集预算，额外音频最多 15%，额外请求最多基线的 30%。风险不是纠错结论。
- `runAsrCoverageReview`：通过 `transcribePart` 回调对选中窗口补听，保留 PCM 哈希、时间范围、接口结束原因、耗时、原稿和逐项补丁。初版接纳要求左右各 4 字锚点唯一、短片 MiMo 与 SenseVoice 在局部候选上精确一致；删除、敏感词变化、歧义锚点等保留为待复核。

[尾部补回工具](../src/asr-coverage-tail.js)提供 `supplementAsrCoverageTail` 和可直接运行复核流程的 `runAsrCoverageReviewWithTail`：

- 原稿至少 24 字，两路短片结果都至少为原稿的 1.35 倍；原稿末尾 6 字在三路文本中都必须唯一匹配，且锚点前的差异比例不超过 20%。
- 至少有 12 字后续内容被短片 MiMo 与 SenseVoice 一致支持，总字数受有效语音时长约束。
- 后续出现分歧时，仅补到已一致部分中的短语标点边界；不修改已有前文，不跳过分歧后继续拼接。
- 对已有否定、数字等内容的修改仍不自动接纳。新增尾部原话可以包含两路一致识别的新事实或否定表达，风险标记仍保留在证据账本；这是初版后单独增加的追加策略，不等于独立听音证明。

所有模型请求仅携带音频；人工参考在复核决定完成后才用于评分。局部参考诊断只在唯一锚点、完整处于核心窗口内的连续非重叠发言上比较，无法评分的变更明确标为 `unscored`。

这些工具已用于真实实验及回放，也有带实际音频回调的可复用接口。**尚未接入浏览器默认转写路径**，没有将实验候选自动推广为生产默认。

| 开发完整录音 | 4 | 7 | 105.870 秒 |
| 开发评分区间 | 1 | 2 | 25.456 秒 |
| 留出完整录音 | 13 | 27 | 389.979 秒 |
| 留出评分区间 | 0 | 0 | 0 |

本次所有触发窗口都装入预算，没有因预算丢弃风险项。新增远端请求为基线的 **14.4%**；提交音频增加 **521.305 秒**，相对完整录音与派生评分区间的实际推理输入量约 **6.93%**。后者只用于计算推理开销，不把派生区间当成独立原始会议时长。

基线墙钟 **377.178 秒**；首次本地扫描 **101.015 秒**，与基线并行；修复微小尾片后重扫 **113.023 秒**；远端复核阶段 **28.281 秒**。没有新增尾部规则的 ASR 请求。

不能只拿 28.281/377.178≈7.50% 宣称端到端开销。按最终本地扫描与远端复核顺序相加，额外阶段相当于基线的 **37.46%**；实际开发还做了首次废弃扫描。冻结后的正式并行流水线需另测墙钟，**本轮未证明此前的端到端耗时增幅不超过 30% 目标**。

## 复现与交付

首次准备新目录（已有实验要续跑时跳过数据准备，保留冻结清单）：

```powershell
python scripts/download-hf-asr-benchmark.py --spec data/hf-asr-coverage-sources.json --output-dir artifacts/hf-asr-coverage
python scripts/prepare-hf-longform.py --root artifacts/hf-asr-coverage
node scripts/eval-hf-longform.mjs --root artifacts/hf-asr-coverage --output-dir artifacts/hf-asr-coverage/baseline --conditions vad30 --dry-run
node scripts/prepare-asr-coverage-plan.mjs

# 两个独立任务可并行执行；Python 环境需安装 sherpa-onnx/numpy，模型已在本地。
node scripts/eval-hf-longform.mjs --root artifacts/hf-asr-coverage --output-dir artifacts/hf-asr-coverage/baseline --conditions vad30 --keys "本地Key备份.json"
python scripts/asr-coverage-scout.py

npm run eval:asr:coverage -- --keys "本地Key备份.json"
npm run eval:asr:coverage:score

# 开发后的尾部规则重放已有声学证据，不调用模型；原初版产物保留。
npm run eval:asr:coverage:tail
npm run eval:asr:coverage:score -- --review-dir artifacts/hf-asr-coverage/review-tail
```

本地 `artifacts/hf-asr-coverage/` 保存完整录音、连续区间、基线、SenseVoice 结果和逐请求音频哈希。`review/experiment.json` 冻结风险计划、策略及依赖哈希；`review/report.json` 保留初版成绩；`review-tail/report.json` 保存开发后回放和补丁诊断。两版目录都输出原始/修复 Markdown 逐字稿，时间标签是窗口范围，不冒充逐词对齐。

`npm run check` 通过：**311 项测试通过、1 项跳过，生产构建成功**。覆盖了预算、源音频一致性、真实重复/删除保护、敏感词、歧义锚点、微小尾片、尾部一致性、取消信号和带音频回调的完整复核流程。新增脚本语法检查和 Python 编译检查通过；两版评分及补丁回放校验通过。

后续验证应固定这一版尾部规则，再选择新的困难留出会议，检查能否发现遗漏并正确补回；同时验证未触发窗口中的漏检，以及并行部署的真实总耗时。当前交付是能运行、能捕获实际漏转并有开发集收益的工具，仍不是追平飞书或普遍提升准确率的证据。
