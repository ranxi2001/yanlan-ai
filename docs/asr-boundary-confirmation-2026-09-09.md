# 美团音频：核心区间唯一发布、边界确认与局部修订

2026-09-09。继续[全场分片验证](asr-window-validation-2026-09-09.md)，本轮解决重叠上下文如何参与确认、如何避免重复拼入逐字稿，以及剩余边界怎样形成有证据的局部修订。

**结果：51个边界中42个取得词面一致性支持，9个待核；对核心逐字稿提交3处最小修订。未宣称人工听校正确率或追平飞书。**

## 1. 从拼接改为核心区间唯一发布

上一轮将带前后各1秒上下文的识别结果直接拼接，仅14个边界完成精确重复前缀裁剪，37个重叠边界未解决。

本轮保存两种资产：

- **核心稿**：52个非重叠、连续覆盖整场录音的约30秒静音切片识别结果。每个核心区间只发布一次。
- **上下文假设**：同样核心区间加前后音频后的识别结果，只提供边界证据，不直接追加到展示文字。

这样可以避免“为去重而误删原话”或“把上下文重复显示”。它不保证核心ASR自身没有重复或漏字，也不保证所有核心文字正确。

`src/asr-boundary-confirmation.js`要求核心与上下文窗口有相同ID、核心时间和连续覆盖；边界两侧分别查找唯一的词面定位片段，并检查左窗口多出的未来内容是否等于右核心开头、右窗口多出的过去内容是否等于左核心结尾。

匹配时只忽略“呃、嗯”，原文保持不变。数字、英文标识符、否定和问号仍参与匹配。遇到歧义、低质量识别、多个定位候选或内容不一致时保留pending，不扩大规则强行确认。

## 2. 真实音频复核结果

复用前轮保存的同音频、同MiMo模型识别结果：`run1/vad30.json`与`run1/vad30_context1.json`。本轮没有重新生成整场核心稿。

| 阶段 | 有一致性支持的边界 | 待核边界 | 新增调用 |
| --- | ---: | ---: | --- |
| 核心稿与已有上下文核对 | 31/51 | 20 | 0 |
| 前12个待核边界回听 | 37/51 | 14 | 18次ASR，约17.401秒墙钟 |
| 补齐剩余8个待核边界回听 | 39/51 | 12 | 14次ASR，约12.712秒墙钟 |
| 稳定局部修订后重新核对 | 42/51 | 9 | 0次ASR、1次语义复核，约18.106秒 |

音频复核先取边界前后各6秒；未确认时再取前后各10秒。32次新ASR请求合计提交480秒音频。第二次扩展执行复用了第一次18条缓存，报告同时记录新请求量与总证据量。

上述约30.113秒ASR复核时间不含此前52条核心和52条上下文识别成本；不能与从零处理一场会议的端到端耗时直接比较。即使边界核对快，整场都生成第二路上下文仍有成本，后续需要验证有选择地生成上下文是否保持收益。

39/51、42/51衡量的是特定证据规则下的边界词面一致性，不是正确识别了相同比例的音频。上一版“14个精确去重”与本轮“31个核心边界支持”的判据不同，不能当作同一指标的准确率增长。

## 3. 对剩余12个边界的处理

`src/asr-boundary-repair.js`在核心边界前后各约20个文字单位内查找小差异，要求：

1. 两份不同长度、同一音频边界的成功ASR证据；同一个窗口复制两次不算两份证据。
2. 修改位置前后各有至少4个连续、唯一匹配的文字单位；两份证据在定位片段之间给出同样内容。
3. 收缩共同前后缀，形成具体片段、UTF-16偏移、before/after；不跨核心片段替换。
4. 数字、英文专名、否定、条件、疑问和停顿词变化不进入自动候选；不通过放宽字符串相似度硬改名字。
5. 候选还需要一次独立语义复核。其职责仅是判定这些局部修改是否有位置证据、是否最小、是否改变实际说法，不重写整篇。
6. 接受后重放精确补丁，保留源文字、源哈希、两份识别文本中的引用跨度及复核结论，再重新执行边界一致性检查。

候选定位实际用时约81.5毫秒，本次产生3处候选，独立复核全部支持。复核使用`gpt-5.6-luna`，1次请求，总Token为2560（输入2197、输出363），无新增ASR请求。相同ASR的两个窗口仍可能共同识别错，所以这些结果不是人工金标准。

| 核心片段起点 | 最小补丁 | 完整表达变化 | 证据范围 |
| --- | --- | --- | --- |
| 01:04 | 着 → 的 | “方式来着” → “方式来的” | 边界64.544秒附近的12秒、20秒音频窗口 |
| 10:53 | 删除“用” | “用做这个数据价值…” → “做这个数据价值…” | 边界653.184秒附近的12秒、20秒音频窗口 |
| 11:51 | 应 → 运 | “开发并应用…” → “开发并运用…” | 边界711.648秒附近的12秒、20秒音频窗口 |

修订后，这3个边界通过了重新核对。其余原话、数字、时间和说话人标签保持不变。当前标签仍是未区分说话人，窗口级时间也没有被包装成精确词时间。

## 4. 改善与限制

使用此前固定的飞书参考差异口径，约30秒静音切片核心稿为20.025%，3处修订后为19.971%，字符编辑距离从1117降到1114。这只说明3个字符层面的差异减少，不能视为广泛识别质量提升。

剩余9个待核边界中包括：

- 普通词面或停顿差异，如“对于/对”“诶/呃”，不一定是业务事实错误。
- 英文产品名的不同结果，如`Vulcan/Vocalo`、`Camada/Knoll/Kernado`，没有用熟悉名字覆盖声学歧义。
- “量化/年化”等会改变含义的疑点，当前未同时满足全部定位和保护条件。
- 原稿问号与音频复识别断句不一致，不能简单忽略问号后宣称通过。
- 长静音附近短复核窗没有覆盖下一句的有效语音，导致证据不足，不说明原文一定错。

本轮消除了“追加上下文造成的新重复”这条错误发布路径，并把可验证的局部修订缩小到3处。没有消除核心识别本身的全部错误，也没有把待核标记删除来美化完成率。
