# 新会议分片消融与上下文投影

实验开始于 2026-09-09，报告日期 2026-09-10。沿用 MiMo v2.5 ASR，比较固定 30 秒、静音边界约 30 秒、静音边界加前后各 2 秒上下文。模型、音频预处理、分片参数和上下文投影算法在读取评分结果之前固定。

**已完成 503 次请求，全部成功，总墙钟 840.456 秒（14 分钟）。静音分片有改善，但未满足全部验收目标；全量上下文候选的额外收益不足以覆盖成本和误改风险。本轮没有修改生产默认转写路径。**

后续已补跑固定/静音 60 秒并定位长窗口漏转，见[60 秒补测报告](hf-asr-60s-2026-09-10.md)。原留出片段 CER 分别为 23.26%/29.30%，不支持改为 60 秒默认。

## 实测结果与决定

以下 CER 只适用于表中说明的连续无重叠片段；错误率越低越好。

| 条件 | 开发 CER，520 字 | 留出 CER，976 字 | 合计 CER，1496 字 |
| --- | ---: | ---: | ---: |
| 固定 30 秒 | 3.46%（18 错） | 15.57%（152 错） | 11.36%（170 错） |
| 静音边界约 30 秒 | 2.50%（13 错） | 14.14%（138 错） | 10.09%（151 错） |
| 静音边界 + 上下文投影候选 | 2.50%（13 错） | 13.63%（133 错） | 9.76%（146 错） |

留出部分的错误类型与耗时：

| 条件 | 替换 | 删除 | 插入 | 边界邻近发言 CER，262 字 | 累计请求耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定 30 秒 | 72 | 45 | 35 | 24.81% | 27.102 秒 |
| 静音边界约 30 秒 | 71 | 27 | 40 | 17.94% | 26.041 秒 |
| 上下文投影候选 | 68 | 29 | 36 | 16.41% | 53.715 秒 |

按事先提出的“留出 CER 相对降低至少 10%、删除/插入不增加、耗时增幅不超过 30%”检查：

- **静音分片：** 留出 CER 相对降低 **9.21%**，主要改善删除错误（45→27）；插入错误增加 5 个，尚未满足质量条件。累计请求耗时约为固定分片的 96.09%，但没有测各组独立墙钟时间，因此不将其当作墙钟验收通过。
- **全量上下文候选：** 留出 CER 相对降低 **12.50%**，但插入比固定分片多 1 个，累计请求耗时为 **1.982 倍**；不接受全量启用。相对静音分片只净减少 5 个编辑错误，却增加约 27.7 秒请求占用。
- 不能改用开发与留出合并后的 11.18% 改善来宣称静音分片达到留出 10% 目标。两个会话、3 个干净区间不足以得出稳定的跨会议收益或飞书对标结论。

完整录音本身的累计请求时间为固定分片 **483.561 秒**、静音分片 **484.249 秒**、上下文候选 **1035.619 秒**。静音分片在完整录音上的请求时间基本持平；不能将干净片段的耗时下降外推到全部会议。

## 上下文的收益与误改

开发干净片段没有接纳任何改变；留出干净片段共有 4 个窗口发生候选替换。将每个替换单独放回原稿、只在本地用金标准评分，得到错误数变化 **0、+1、-2、-4**：存在有效修正，也确实存在误改。它们都是离线诊断，未用金标准选择候选。

具体例子：`L_R004S01C01-clean-2` 第 1 号窗口将“水果儿了”改成“水果啦”，该次孤立替换少 2 个编辑错误；`L_R004S01C01-clean-1` 第 1 号窗口主要改变儿化/停顿词，该次孤立替换多 1 个错误。减少整体 CER 不能证明每处修改都正确。

直接拼接扩展窗口作为对照会明显重复上下文：开发干净片段的 CER 为 **11.15%**，锚点投影后为 **2.50%**。这是同一批扩展识别输出上的投影对照，没有额外模型调用。由此能确认“正文归属处理”有必要，仍不能证明投影内部的候选一定正确。

完整开发/留出录音分别产生 25/26 个改变正文的上下文候选。后续风险检查发现其中共有 3 处否定标记序列变化；这不是 3 处已确认识别错误，而是必须听音复核的事实极性差异。完整录音的这些候选没有假借干净片段 CER 获得自动批准。

4 次固定窗口重复请求中，2 次归一化文字相同，另 2 次分别相差 2、1 个字符，证明 API 存在波动；没有把单次几字符差异表述成确定性收益。

下一轮应优先压低静音分片新增的插入错误，并用不读取金标准的风险触发器选择少量补听片段。补听同时计入原片与复核成本，以新的留出会议验证纠错/误改比例；本轮证据不支持扩大为全稿重写或无条件上下文替换。

## 数据与评测边界

从 [AISHELL/AISHELL-4](https://huggingface.co/datasets/AISHELL/AISHELL-4) 的固定 revision `aada72727856313b19d4a030383c426364931dbf` 下载两场新会议，均未出现在上一轮 320 条基准中。

| 用途 | 会议 | 完整时长 | 单独解码并计算严格 CER 的连续区间 |
| --- | --- | ---: | --- |
| 开发 | M_R003S01C01 | 2282.210 秒 | 1490.350–1690.558 秒，200.208 秒 |
| 留出 | L_R004S01C01 | 2195.433 秒 | 177.556–313.396 秒、880.882–992.506 秒，共 247.465 秒 |

两场完整录音共 **4477.643 秒（74 分 38 秒）**，三组都实际识别完整录音并输出逐字稿。严格 CER 另外在 **3 个连续片段、447.672 秒（7 分 28 秒）** 上计算；它们是原会议的派生片段，不能与完整会议时长相加当成独立数据量。

干净片段选择规则：先排除含特殊标签的整条发言、发生跨说话人重叠的整条发言并取并集，再保留其余连续区间中至少 60 秒的部分；保留真实停顿，不拼接分散发言。最终按实际首尾发言裁边后仍要求 60 秒。选择使用人工时间/重叠标注，因此这是条件化的分片诊断，不是生产系统自行发现干净区间的成绩。

完整录音包含重叠发言，**不将其参考文本按开始时间串接后当作普通 CER**。本轮没有给完整会议或重叠部分赋予 CER，也没有用干净片段分数替代完整会议质量。

原始八声道 FLAC、TextGrid、RTTM 保留在本地忽略目录。推理取声道 0、16 kHz PCM16，不平均阵列通道。来源与哈希见[来源规格](../data/hf-asr-longform-sources.json)、[固定清单](../data/hf-asr-longform-lock.json)。许可证沿用[数据说明](hf-asr-benchmark-2026-09-09.md)中记录的上游/HF 差异，音频没有纳入代码提交。

## 冻结条件

| 条件 | 分片 | 正文来源 | 独立运行的成本口径 |
| --- | --- | --- | --- |
| fixed30 | 连续固定 30 秒 | 原片 ASR 原文 | 原片请求 |
| vad30 | 目标 30 秒，20～40 秒；优先静音中点 | 原片 ASR 原文 | 原片请求 |
| vad30_context2 | 与 vad30 相同的核心区间，前后各扩展最多 2 秒 | 唯一锚点裁剪后的实验候选；失败退回原片 | **原片请求 + 扩展片请求** |

Silero VAD 使用 faster-whisper，threshold=0.5，最短静音 300 ms，speech padding=0。只选切点，不删除静音或未检出的语音。三组语言均为 auto，只发送音频，无词表、参考文本或 LLM 重写。并发为 2，按窗口序号交错各组请求，两个完整会话各重复 2 个固定窗口以观察 API 输出波动。

上下文投影使用核心原文首尾各 8 个归一化字符作为锚点，要求锚点在原文和扩展识别中各唯一、顺序正确，且处于允许的上下文范围。只替换两锚点之间的文字，保留原片前缀/后缀；改动量超过 `max(2, floor(核心字符数 × 15%))` 时退回原片。保留原文、候选、偏移和证据区间，可精确回放；窗口时间不冒充逐词时间。

开发片段结果出现后没有调整这些规则，再按相同配置完成留出会话。唯一会话的留出不等于统计充分的泛化验证。

## 指标

CER 沿用上一轮 NFKC、小写、去空白/标点/符号的字符评分，保留真实停顿词，不做简繁、数字或语义同义转换。按参考字符数微平均，分别报告替换、删除、插入。

边界指标使用三组全部切点的并集，并将接触切点前后 1 秒的**整条参考发言**标为边界邻近区域，使三组使用相同参考字符。没有人工逐词时间，不能称为精确的“边界前后 1 秒 CER”。插入错误归到它之前的参考字符；对齐规则与整体 CER 一致。

相邻输出的相同后缀/前缀仅作为重复候选告警，可能是真实重复发言，不直接计为重复错误，也不自动删除。普通 CER 的插入错误也不全是重复内容。

耗时报告累计请求时间，包括网络和服务端处理；由于各条件交错运行，不把它当作每组独立墙钟耗时。上下文组没有省略核心识别成本。

## 上下文接纳的限制

在开发完整录音 `M_R003S01C01-full-0` 的第 20 号 VAD 窗口，原片出现“让家长不放心”，扩展识别候选变为“让家长放心”，即使两端锚点匹配。这只是文本之间的事实极性差异，尚未逐条听音仲裁，不能据此认定某一路正确。

新增 `reviewAsrContextProposal` 对否定、数字、英文标识符、情态和疑问差异作风险标记。**任何发生变化的候选都需复核，默认发布仍为核心原文**；没有敏感标记也不会自动批准。这个检查是在发现开发案例后添加的诊断层，没有修改已冻结的上下文实验成绩，也没有用它在留出数据上重新挑选收益。

## 复现与产物

```powershell
python scripts/download-hf-asr-benchmark.py --spec data/hf-asr-longform-sources.json --output-dir artifacts/hf-asr-longform
# Python 需具备 numpy、faster-whisper；ffmpeg 在 PATH。
python scripts/prepare-hf-longform.py
npm run eval:asr:longform -- --dry-run
npm run eval:asr:longform -- --keys "本地Key备份.json"
npm run eval:asr:longform:score
```

实际音频、请求缓存与全文位于 `artifacts/hf-asr-longform/`。`evaluation/experiment.json` 保存冻结条件及算法哈希，`runs.json` 保存完整输出；`report.json` 保存统一评分、边界指标、逐处候选诊断及验收条件。各会话、各条件的 Markdown 逐字稿保存在同一目录，带上下文者明确标为未经审核的实验候选。

准备脚本验证原音频和标注 SHA-256；推理脚本验证 PCM 哈希、时长、冻结计划与缓存窗口，支持完成请求的断点复用。评分脚本检查参考哈希、干净区间无重叠、各组完整覆盖和上下文投影回放。推理脚本不读取参考文件。

新增可复用工具：[上下文正文投影](../src/asr-context-projection.js)、[候选复核门](../src/asr-context-review.js)、[边界错误定位评分](../src/asr-boundary-metrics.js)。它们已经在实际实验/评分中调用，但没有接入浏览器默认转写流程。

验证：最终完整测试 297 项通过、1 项跳过；本轮 `npm run check` 的语法检查和生产构建通过。新增 Python 准备脚本编译检查、JS 实验与评分脚本语法检查通过；实际 503 次请求完成，评分与投影回放校验通过。
